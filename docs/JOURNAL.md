# Журнал разработки Core

Рабочая память проекта: как всё устроено, почему именно так, что менялось и что
отложено. Пишется для того, кто продолжает работу без памяти о прошлых разговорах, —
в первую очередь для Claude после того, как кончилось контекстное окно.

**Правило:** после каждого заметного изменения — дописать запись в «Хронику» и, если
поменялось устройство, поправить нужный раздел. Журнал, который отстал от кода, хуже,
чем никакого.

---

## 1. Как мы работаем

- **Кто и что.** Один человек, личное Android-приложение для себя. Общение по-русски.
  Объяснять простыми словами; если что-то непонятно — объяснить, а не отмахнуться.
- **Репозиторий.** `nonedeity-dotcom/Core` (старое имя `demo_klic` тоже работает, GitHub
  перенаправляет). Приложение — в `mobile-app/`.
- **Ветки.** Каждый коммит пушится **в обе**: `claude/tracker-app-demo-8eowpg` и
  `claude/balance`. CI собирает только первую.
  ```bash
  git push origin HEAD:claude/tracker-app-demo-8eowpg && git push origin HEAD:claude/balance
  ```
- **Сборка.** Пуш в `claude/tracker-app-demo-8eowpg` → GitHub Actions «Build Android APK»
  (~10–12 мин) → релиз `android-build-<номер запуска>` с APK.
  Ссылка: `https://github.com/nonedeity-dotcom/Core/releases/download/android-build-N/app-release.apk`
- **Постоянные договорённости:**
  - Когда сборка готова — **самому присылать ссылку на APK**, не дожидаясь вопроса.
  - Большие изменения интерфейса — сначала показать (прототип, скриншоты), потом ломать.
  - Честно говорить об ограничениях: что не проверено на телефоне, что не получилось.
  - Перед тем как делать список идей — спросить; «пока ничо не делай» значит только
    обсудить.
- **Коммиты** — по-русски, заголовок про то, что изменилось для человека, в теле —
  почему и как проверено.

## 2. Устройство приложения

**Стек:** Expo SDK 51, React Native 0.74, TypeScript, `@tanstack/react-query`,
`react-native-svg`. Сервера нет, аккаунта нет — всё на телефоне. `backend/` в корне —
остаток первой версии, не используется.

### Хранилище
- Всё лежит в `AsyncStorage`, доступ только через `src/api/client.ts` (объект `api`).
  Ключи — в `KEYS` в начале файла (`habits-list-v1`, `habit-log-v1`,
  `rewards-purse-v1`, `game-stats-v1`, `screen-days-v1` и т.д.).
- Запись под блокировкой ключа: `withKeyLock` / `withAllKeyLocks`. Всё, что читает-меняет-
  пишет, делает это **внутри одной блокировки** — иначе две быстрые записи затирают друг
  друга (так уже было с кошельком).
  - `api.updatePurse(fn)` — единственный способ поменять кошелёк. `setPurse` удалён
    нарочно. На экранах — хук `useSavePurse()`.
  - `api.updateGameStats(fn)` — то же для статистики игр.
  - `api.bumpHabit` — один тап по привычке: +1, до цели, назад не ходит.

### Навигация
- Нижняя панель `SectionBar`: **Главная · Sterzhen · CaloriX · Creker · Ещё**.
  Раздел Sterzhen пишется латиницей — так попросили.
- «Ещё» → Игры, Магазин, Профиль, Настройки.
- Разделы с вкладками рисуются `TabbedSection` + `TabChips` (вкладки сверху).
  - Sterzhen: Отчёт · Чек-лист · Фокус · Энергия · Статистика.
  - CaloriX: Дневник · Статистика · Профиль.
- История разделов живёт в `RootTabs`, аппаратная «назад» снимает по одному разделу.
- Отдельные экраны открываются через Stack в `src/navigation/RootTabs.tsx`: Settings,
  Admin, Goals, WordSearch, Wheel и т.д.

### Разделы
- **Sterzhen** — привычки и фокус. Три группы: «Ввожу сейчас» (решает день),
  «Дополнительно», «Потом». Серии, заморозки, выходные, уровни привычек, цели на
  месяц/год. Логика — в `src/lib/` (`streak.ts`, `dayRule.ts`, `level.ts`, `habits.ts`,
  `goals.ts`…).
- **CaloriX** — еда, вес, вода, прогноз веса (`src/lib/balance/`).
- **Creker** — экранное время. Приложение считает его само (`usageSync.ts`, нужен доступ
  к статистике использования); раньше читало из отдельного приложения creker через
  ContentProvider — этот путь остался запасным (`syncFromCreker`).

### Экранные привычки (`src/lib/screenTime.ts`, `src/integrations/screenTime.ts`)
- Правило: `ScreenRule { app, label?, limitMin, direction?: "atMost" | "atLeast" }`.
  `app = ".total"` — всё экранное время.
- `decideRule` несимметричен нарочно:
  - «не больше»: превышение окончательно сразу, а «уложился» — только по свежим данным;
  - «не меньше»: «набрал» окончательно сразу, а «не набрал» — только за законченный день
    со свежими данными.
- `refreshScreenHabits` сначала обновляет цифры (не чаще раза в 60 с), потом судит
  вчера и сегодня. Ручная отметка сильнее автоматической.

### Награды (`src/lib/rewards/`)
- Две валюты: **искры** (частые, на подсказки) и **ядра** (редкие, на то, что навсегда).
  За что и сколько — `earn.ts` (`SPARKS`, `CORES`). Каталог и титулы — `catalog.ts`.
- **Оплата по ключам.** Каждое событие имеет ключ (`day:2026-09-14`, `wheel:12`…) и
  оплачивается один раз; оплаченные ключи хранятся в кошельке (`purse.paid`).
- **Журнал дней (`ledger.ts`).** Прошедший день рассчитывается один раз, через
  `SETTLE_LAG_DAYS = 2` дня после конца, и записывается. Смена правил задним числом
  ничего не доплачивает и не отнимает. Вехи и титулы считаются по журналу за всё время.
- `useRewards` ждёт, пока загрузятся **все** запросы, и только потом рассчитывает — иначе
  пустое прошлое записалось бы навсегда.
- Сегодняшняя еда, вес, экран и фокус не оплачиваются: день ещё не закончен.
- Экранная награда и титул «Отключённый» — только за привычки «не больше».

### Игры (`src/lib/games/`, `src/screens/games/`)
- **Найди слова** (`wordsearch.ts`): поле собирается на месте, темы в
  `src/content/wordThemes.ts` (часть открывается за ядра).
- **Колесо букв** (`wheel.ts`): 300 готовых уровней в `src/content/wheelLevels.json`.
  - Уровни собираются скриптом `tools/wheel/build-levels.js` из dictionary-ru (BSD,
    © Lebedev) и FrequencyWords (MIT, © Hermit Dave). В скрипте есть список запрещённых
    корней: мат, оскорбления, насилие. После пересборки — проверить глазами.
  - Прогресс недоигранного уровня хранится в `gameStats.wheel.progress`.
  - Награды: 5 искр за уровень, 5 искр за каждые 10 бонусных слов. Титул «Словесник» —
    за 50 уровней.
- Статистика игр при слиянии копий: счётчики — максимум, рекорд — лучший, колесо — кто
  дальше ушёл.

### «Опушка» — большая спокойная игра (`src/lib/village/`, `VillageScreen.tsx`)
- Владелец хочет **одну игру, которая растёт годами**: лес и деревня, без спешки,
  выживание мягкое. Добавлять можно что угодно (ферма, рыбалка, жители, пещеры).
- **Время идёт только от действий.** Шаг — 2 мин, собрать — 5–45 мин. Голод на нуле
  замедляет вдвое, но не убивает. Ночь 21–6: темнеет, спать у костра или в домике.
- **Мир не хранится.** Он выращивается из зерна (`world.ts`, 64×64: поляна в центре,
  лес, пруд, край — сплошной лес). В сохранение (`village-v1`) идут только перемены:
  `used` (когда клетку собрали — от этого зависит, отросло ли), `built`, сумка, время.
- **Как добавлять новое:** справочники в `content.ts` (ITEMS, NATURE, STRUCTURES,
  RECIPES, GOALS), картинка — случай в `components/village/Sprites.tsx` (SVG, не эмодзи).
  Правила в `game.ts` — чистые функции `move/act/craft/place/pickUp/eat`, каждая
  возвращает `{state, message}`. `id` из справочников попадают в сохранения — не
  переименовывать.
- Ветки и камешки подбираются, когда на них наступаешь. Остальное — лицом к клетке и
  кнопка действия.
- Короткий тап по стрелке на вебе приходит без `onPressIn` — поэтому шаг есть и в
  `onPress`, с флагом `stepped`, чтобы не шагнуть дважды.
- **Интерфейс** (`components/village/`): `VillageMap` — мир сдвигается целиком
  анимацией (`Animated.ValueXY`), персонаж стоит в центре; клетки ключуются мировыми
  координатами и мемоизированы — на шаге рисуется только новая полоска. `CellArt` —
  одна SVG на клетку (земля + мелочи по `variant()` + природа + постройка). `ItemIcon` —
  значки вещей. `Controls` — круглая крестовина, кнопка действия со значком цели,
  круглые кнопки. `BagSheet` — «Вещи» плиткой и «Ремесло» с «есть/нужно» по каждому
  ингредиенту.
- **Ходьба по касанию:** `pathTo` (поиск в ширину) — нажал на клетку, дошёл; нажал на
  дерево — дошёл и встал лицом; нажал на то, к чему уже лицом, — действие.
- **Поворот экрана:** `app.json` → `"orientation": "default"`, но `App.tsx` сразу
  держит всё вертикально (`src/lib/orientation.ts`, модуль `expo-screen-orientation`).
  Горизонтально ложится только «Опушка» — по кнопке в углу, выбор хранится в
  `village-ui-v1`. Горизонтально размер карты берётся из окна, а не из замера рамки:
  замер после поворота приходил от старой рамки, и карта была на пол-экрана.
- Едет в резервной копии (раздел Sterzhen). При слиянии побеждает копия, где прожито
  больше игрового времени: два мира смешивать нельзя.
- Сделано в первой версии: сбор, топор, кирка, костёр, верстак, забор, домик, задачи для
  начала, день/ночь, сытость. **Идеи дальше:** огород, рыбалка (у воды уже написано
  «здесь будет удочка»), сундук, животные, жители и торговля, пещеры.

### Резервная копия (`src/lib/backup.ts`)
- Копия бывает общей или по разделу. Кошелёк и игры едут в разделе Sterzhen.
- `purse` / `gameStats` = `null` значит «в файле этого нет, текущее не трогать».
- Слияние: деньги не складываются, купленное объединяется.

### Акцентный цвет
- Выбирается в Профиле и применяется при запуске: `App.tsx` читает кошелёк, ставит
  `colors.accent`, и только потом грузит экраны.
- Экраны грузятся через `require`, а не `import()`: динамический импорт ломает веб-сборку.

### Виджет «Сегодня» (`modules/core-widget/`, `src/integrations/widget.ts`)
- Нативный модуль на Kotlin: `HabitsWidgetProvider`, `WidgetRender` (RemoteViews),
  `WidgetStore` (SharedPreferences).
- Показывает привычки «Ввожу сейчас» на сегодня.
- Приложение кладёт слепок `{date, habits:[{id,label,count,target,auto}]}` через
  `setWidgetSnapshot`.
- Нажатие на виджете встаёт в очередь `pending` и сразу рисуется отмеченным. При
  открытии приложение забирает очередь (`takeWidgetTaps`) и делает `bumpHabit` на каждое
  нажатие.
- Экранные привычки на виджете не нажимаются. Слепок со вчера показывается с нулями.
- Хук `useWidgetSync()` вызывается в `RootTabs`.

### Второй нативный модуль
`modules/creker-usage/` — события использования, имена и иконки приложений, чтение из
creker. Оба модуля подхватываются автолинковкой из `./modules` (см. `package.json`).

## 3. Проверка

- **`npm test`** (в `mobile-app/`) — `tsc -p tests` + `node tests/run.js`, без
  библиотек. Тесты в `tests/*.test.ts`, свой мини-набор в `tests/harness.ts`. Около 2850
  проверок, из них ~2700 — по девять на каждый из 300 уровней колеса. Даты в тестах —
  относительно сегодня.
- **`npx tsc --noEmit`** — типы.
- Оба шага стоят в CI **до** Gradle: упавшая проверка останавливает сборку.
- **Проверка в браузере** (dev-сервер здесь не поднимается):
  1. `npx expo export --platform web`
  2. `cd dist && python3 -m http.server 8099` (фоном)
  3. Скрипт Playwright: `NODE_PATH=/opt/node22/lib/node_modules /opt/node22/bin/node script.js`,
     браузер `executablePath: '/opt/pw-browsers/chromium'`.
  4. Данные сеются в `localStorage` под теми же ключами, что в `KEYS`, потом `reload`.
  - Скрипты лежат во временной папке сессии и **пропадают** — при нужде писать заново.
  - Не делать `pkill -f "http.server 8099"` в одной команде с другими: pkill убивает
    собственную оболочку (код 144).
- **Kotlin без Android SDK:** `bash tools/kotlin-check/check.sh` компилирует виджет
  против заглушек. Ресурсы, манифест и Gradle это не проверяет — это делает только CI.
- **Автолинковка:** `npx expo-modules-autolinking resolve --platform android` покажет,
  видит ли Expo модули из `modules/`.

## 6. Грабли (на чём уже спотыкались)

- Переписал файл целиком через Write и потерял в нём функции (`syncFromCreker`).
  Большие файлы править через Edit, а при сомнении сверяться с `git show HEAD:путь`.
- Эффект с зависимостью только от `habits.length` не видел смены правила привычки.
  Нужен «слепок» правил в зависимостях.
- `applyAwards` перечислял поля кошелька и терял новые. Теперь `...purse`.
- В сгенерированных словах нашлось оскорбление. Список запретов расширен; после любой
